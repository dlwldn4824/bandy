## W. 화면 → 백엔드 연결 (Supabase 모드를 실제 서버 없이) (P0)

### W-0. 방법
- 실제 GoTrue·PostgREST는 이 환경에서 실행 금지라, **부록 F의 가짜 게이트웨이**(Node, 약 150줄)를 쓴다. 이번 검토에서 동작 확인함.
  - `/auth/v1/signup`, `/auth/v1/token?grant_type=password|refresh_token`, `/auth/v1/user`, `/auth/v1/logout` (HS256 JWT 발급)
  - `GET /rest/v1/<table>?select=*` → 트랜잭션 안에서 `set local role anon|authenticated` + `request.jwt.claims` 설정 후 `select * … limit 1000`(Supabase 기본 Max Rows 흉내)
  - `POST /rest/v1/rpc/<fn>` → `pg_proc`에서 인자 이름·타입을 읽어 `public.fn(p_x => $1::type …)` 호출. STABLE 함수는 읽기 전용 트랜잭션(PostgREST와 같음)
  - 오류 본문 `{code, message, details, hint}`, SQLSTATE→HTTP 상태는 PostgREST 규칙(42501→401/403, 23505·23503→409, P0001→400 등)
  - 모든 요청을 `GW_LOG`(JSONL: method, path, table/fn, status, bytes)에 기록 → 성능(P 묶음)에 사용
- **한계(실제 Supabase에서 다시 볼 것, R 묶음)**: 실제 JWT 서명 검증·만료 처리, 메일 인증, 카카오 OAuth, PostgREST의 정확한 응답 헤더·오류 문구, 요청 크기 제한, 네트워크 지연.

## P. 성능 측정 (P1)

### P-1. 재조회 요청 수·응답 크기(W 환경)
- 방법: 각 동작 전 `: > $WORK/gw.jsonl`, 동작 후 `jq -s '{n: length, gets: map(select(.method=="GET"))|length, bytes: (map(.bytes)|add)}' $WORK/gw.jsonl`.
- 동작: 첫 화면(비로그인), 로그인 직후, 예매 1회, 입금 확인 1회, 입장 처리 1회, 알림 하나 읽음, 탭 숨김→보임(`page.evaluate`로 `visibilitychange` 두 번), **두 번째 페이지를 열었다가 원래 페이지를 `bringToFront()`**(실제 가시성 변화).
- 기준(제안): 변경 1회당 GET ≤ 3, 입장 처리 1회 응답 합계 ≤ 50KB, 탭 복귀 시 GET 0. 현재 예상: 변경마다 GET 13(review H4), 탭 복귀는 미확인(L10).

## M. 마이그레이션 호환(팀 초기 SQL 가정) (P2)

팀 원본 `202610140001_bandy_initial_schema.sql`은 저장소에 없다(review H3). 원본을 받기 전에는 **노션에서 보이는 차이를 모사**해 영향만 측정한다.

| ID | 절차 | 기대 / 판정 |
|---|---|---|
| M-1 | `newdb review_tp_compat nofixture`를 쓰지 말고 직접: 새 DB → shim → `create table public.events (...)`를 migration과 같은 컬럼 + `check (status <> 'PUBLISHED' or (address is not null and ends_at is not null and admission_starts_at is not null and admission_ends_at is not null and published_at is not null))`로 먼저 만들기 → migration 적용 → fixture 없이 동아리·운영진 준비 → `create_event(..., publish true)` | 현재 예상: CHECK 위반 원문. 결과 기록(원본 SQL에 같은 CHECK가 있으면 H3 확정) |
| M-2 | migration 적용 전 `create function public.team_helper() returns boolean language sql as 'select true'; create policy … using (public.team_helper())`(예: profiles) → migration 적용 → authenticated로 profiles 조회 | 'permission denied for function team_helper'가 나면 전역 revoke 영향 확인(H3) |
| M-3 | migration 전 `create table public.legacy_x(id int); grant select on public.legacy_x to anon` → migration → anon 조회 | 거부되면 '다른 public 테이블 권한 회수' 확인(H3) |
| M-4 | 트리거 없이 만든 auth 사용자(D8과 같음)로 W 흐름 로그인 | 화면이 로그인 안 된 것처럼 보이면 FAIL(H3) |

원본 SQL을 받으면: 빈 DB → shim → **원본 SQL** → 이 migration → T0-1·D·S·C 전체 재실행. 이것이 R-1의 리허설이다.

      const v = r.rows[0].r
      return send(res, 200, v === '' ? null : v, { ...meta, fn: f.proname })
    }

    if (tbl && req.method === 'GET') {

# BANDY 프로토타입 (`/app`)

기능 흐름을 확인하는 화면 프로토타입입니다. 두 가지 모드로 돕니다.

- **Supabase 모드:** `.env`에 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`가 있으면 실제 Supabase DB 함수를 부릅니다. 로그인은 이메일(가입·로그인)과 카카오(Supabase 설정 후). 적용 방법은 `supabase/README.md`.
- **데모 모드:** 환경변수가 없으면 브라우저(localStorage)에 저장하고, 시연 역할(관객 / 렉사 운영진 / 멜로딕 운영진 / 밴디 운영자)로 로그인합니다.

```bash
npm run dev        # http://localhost:5173/app
```

기존 단일 공연 앱(`/login`, `/manage` 등)은 그대로 두고, `/app` 아래에서 Firebase·분석 연결 없이 따로 돕니다.

## 기준

- **화면 구조와 흐름:** 피그마 「UX plan」의 정보구조도(로그인 → 홈 → 하단 메뉴와 하위 화면)와 관객·운영자 user flow만 따릅니다. 피그마의 시각 디자인(색·카드·아이콘·이미지)은 쓰지 않습니다.
- **기능 범위:** 위 구조도 + 11/1 회의에서 12월 전 필수로 정한 기능(동아리 찾기, 교류 신청, 입금자명 예매와 입금 확인).
- **UX/UI 범위:** 흐름과 구조를 파악할 수 있을 정도만 구현합니다. 화이트 + 레드 기본형이고, 장식 요소(아이콘, 그림자, 빈 이미지 자리, 집계 상자 등)는 넣지 않습니다. 포스터·프로필 이미지는 올린 경우에만 보입니다.

## 화면 (구조도 기준)

| 구조도 | 화면 | 경로 |
|---|---|---|
| ① 로그인 · 회원 유형 | 개인 / 동아리 회원 선택 (프로토타입은 시연 역할) | `/app/login` |
| ② 홈 | 검색창 · 알림 버튼 · 공연 홍보 · 실시간 공연 소식 → 전체 보기 | `/app` |
| 공연 검색 결과 · 전체 공연 목록 | 검색어, 분류, 정렬(공연일 · 최신 등록 · 예매 많은 순 · 가까운 순) | `/app/events` |
| 알림 목록 | 읽음 처리, 관련 화면으로 이동 | `/app/notifications` |
| 하단: 지도 · 캘린더 | 지도(내 위치 반경 1 · 3 · 5km) / 캘린더(날짜 선택 → 공연 목록) | `/app/map` |
| 하단 가운데 (개인) | 내 티켓: 입금 대기 → 입장 예정 → 이후 공연 → 사용 완료 → 지난·취소된 공연, 선택하면 QR | `/app/tickets` |
| 하단 가운데 (동아리) | + 공연 등록 → 메뉴(공연 등록 / 동아리 등록·수정). 승인된 동아리의 운영진만. 운영진 본인의 티켓은 마이페이지 → 내 티켓 | `/app/manage/:clubId?tab=new` |
| 하단: 동아리 찾기 | 장르 · 지역 · 교류 열림 필터 / 교류 신청함 | `/app/clubs` |
| 하단: 마이페이지 | 개인: 프로필 · 예매 내역 · 알림 설정 · 계정 설정 / 동아리: 동아리 프로필 · 공연 관리 / 운영자: 동아리 승인 | `/app/my` |
| 공연 상세 → 예매 화면 → 예매 완료 | 티켓 종류 · 수량 → 입금자명 → 계좌 안내 | `/app/e/:id`, `/app/e/:id/book` |
| 동아리 페이지 | 프로필 · 공연 · 가입 신청 · 교류 신청 · (교류 수락 시) 오픈채팅 | `/app/c/:id` |
| 공연 관리 | 공개/비공개 · 수정 · 공연 취소 · 삭제 · 예매자 목록 · 입금 확인 / 부원(가입 수락 · 운영진 지정) | `/app/manage/:clubId` |
| 공연 등록 / 동아리 등록·수정 | 포스터 · 프로필 이미지 업로드 포함 | `/app/manage/:clubId`, `/app/clubs/new` |
| 입장 관리 (운영자 흐름) | QR 스캔 → 검증 → 관객 정보 확인 → 입장 처리 | `/app/scan/:eventId` |

구조도에서 '보류'였던 **동아리 찾기**는 11/1 회의에서 필수로 바뀌어 넣었습니다. **네트워킹(NFC)** 은 구조도대로 이후 추가입니다.

## 모바일 편의 (`convenience.tsx`, `device.ts`)

| 기능 | 동작 | 서버 신호 |
|---|---|---|
| 앱을 열면 바로 보기 | 곧 시작하는 공연 → 입장 QR / 오늘 운영하는 공연 → 입장 관리 / 기한 임박 입금 → 계좌 안내. 닫으면 6시간 동안 다시 안 띄움 | `my_home_state().prompt` |
| 홈 상단 카드 | 다음 티켓, 오늘 운영 공연(입장·입금 대기 수), 입금 대기(계좌 복사 · 입금했어요), 처리할 가입·교류 신청 | `my_home_state()` |
| 입금했어요 | 예매자가 누르면 주최 운영진에게 알림, 운영진 목록 맨 위에 '입금했다고 알림' | `mark_deposit_sent` |
| 로그인 유지 | Supabase 세션을 기기에 저장·자동 갱신(`bandy-auth`), 마지막 이메일·시연 역할 기억 | Supabase Auth |
| 로그인 후 돌아가기 | 로그인 링크에 `?next=`(앱 안 주소만 허용), 카카오 로그인도 같은 화면으로 | — |
| 티켓 바로 열기 | `/app/tickets?open=티켓ID`, 알림을 누르면 처리할 화면으로 | — |
| QR 보기 편의 | QR을 띄운 동안 화면 꺼짐 방지, 전파가 약하면 이 기기에 저장된 마지막 QR(24시간 안) 표시 | `issue_ticket_qr` |
| 앱으로 돌아오면 새로고침 | 은행 앱 등에서 돌아오면(30초 이상 지났을 때) 다시 읽음 | — |
| 홈 화면에 추가 | `/app`에서만 manifest·아이콘을 붙임(`public/bandy/`), 마이페이지에 안내 | — |
| 입금자명 기억 | 마지막에 쓴 입금자명을 다음 예매에 미리 채움 | — |
| 공연 진행 시간 | 공연 등록·수정에서 진행 시간(분) 입력, 상세에 '19:00 ~ 21:00 (120분)' | `events.ends_at` |
| 일정 변경 선택 | 일시·장소가 바뀌면 홈 창 + 내 티켓 '확인이 필요해요'에서 유지 / 취소·환불 요청(환불 계좌 입력) | `my_home_state().changed_bookings`, `ack_event_change`, `request_refund` |
| 환불 처리 | 공연 취소 시 확정 예매자도 환불 요청, 운영진 공연 관리에 환불 요청 목록·'환불 완료' | `refund_requests`, `mark_refunded` |

로그아웃하면 이 기기에 남긴 QR·입금자명을 지웁니다(마지막 이메일은 남김).
다른 계정으로 로그인하면(로그아웃 없이도) 앞 사람의 QR·입금자명을 지웁니다(공용 기기).

운영 빌드는 Supabase 키가 없으면 '서버 설정이 빠졌어요' 화면을 띄웁니다. 시연용 배포만 `VITE_BANDY_DEMO=true`로 데모를 엽니다(데모 화면 위에 '시연용' 띠). 실사용 전환 할 일은 `docs/bandy-운영전환-체크리스트.md`.

## 임시로 정한 값 (팀 결정 필요)

- 입금 대기 3일, 1회 최대 10장 (`repo.ts` 상단)
- 무료 공연은 입금 확인 없이 바로 확정
- 입금 확인 후 취소 · 환불 없음. 예매 기록이 있는 공연은 삭제 불가(비공개만 가능), 예매가 있으면 가격 변경 불가
- '입장 예정'은 공연 시작 24시간 전부터. 시작 시각이 지난 공연은 피드·지도·캘린더에서 빠지고 예매 마감
- 운영진(입금 확인·입장 처리) 추가: 부원 가입 신청 → 수락 → 회장이 운영진 지정 (구조도에 없던 화면, 검토에서 '운영진 1명뿐' 문제로 추가)
- 데모 시연 공연 날짜는 오늘 기준 며칠 뒤로 자동 설정(`seed.ts`). 처음 연 날 기준으로 저장되므로 시간이 지나 지난 공연이 되면 마이페이지 '시연 데이터 처음으로 되돌리기'로 날짜를 새로 잡음
- 홍보 공연 선정 기준: 지금은 피드 상위 3개
- 알림 설정은 화면에 저장만 하고 발송 방식은 미정
- 입장 후 '기존 서비스' 연결은 기존 `/performances`로 임시 연결
- 서비스 이름 `BANDY` (`components.tsx`의 `APP_NAME` 한 곳만 바꾸면 됨)
